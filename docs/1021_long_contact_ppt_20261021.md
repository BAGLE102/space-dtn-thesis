## 使用的拓譜

採用 `configs/long_contacts_20261021/experiment.json` 主版本，容量為速率×時窗長度，**不是**沿用原quota的對照版。

- 節點：X、A、B、C、D；各Buffer 4MB。兩包各4MB，生成時間分別0與1秒。
- Contacts：c1[2,12]、c2[8,18]、c3[1,11]、c4[12,28]、c5[20,36]、c6[1,18]、c7[16,30]、c8[4,14]。
- 速率4MB/s，傳輸需1秒；c2/c5/c6傳播延遲1秒，其餘0。期限40秒。
- 初始R依c1～c8為 `(40,40,40,64,64,68,56,40)` MB。

因此原短時窗簡報的「c2已用完、c7只有2MB、c8已來不及」不能直接沿用，已重新推導情節與數值。

## 解析圖解與具體排程

第一包選擇c1起送2秒、B於3秒完整抵達，c2起送8秒、D於10秒完整抵達。B占用：2～3秒上升到4MB、3～8秒持有、8～9秒釋放。D於9～10秒接收，在10秒完整交付後釋放，交付前峰值仍計算。

在此已接受狀態下，對第二包解析得到：

| 項目 | 區間／條件 |
| --- | --- |
| c3的可起送時間J | `{1} ∪ [8,10]` |
| c3的完整抵達時間 | `{2} ∪ [9,11]` |
| B可完整持有4MB的W_B | `[0,2] ∪ [9,40]` |
| c6的完整抵達C區間 | `[3,19]` |
| c8的可起送時間J | `[4,8] ∪ [10,13]` |
| c8的完整抵達D區間 | `[5,9] ∪ [11,14]` |

c8的缺口來自D在9～10秒的既有接收占用，不是只有傳送預約。邊界s=8及s=10可取，分別對應新包在第9秒交付，以及在第10秒開始接收；須保留瞬間峰值規則。

第二包選c6起送1秒、C完整抵達3秒，等待至4秒，以c8發送4～5秒，D於5秒完整抵達。最後容量為 `(36,36,40,64,64,64,56,36)` MB，新增F為c6[1,2)、c8[4,5)。B及C分屬不同節點，各自峰值4MB，不能把兩者占用相加與單一節點上限比較。

規劃先後不限制抵達先後：先接受第一包的排程，再規劃第二包，仍可能第二包在更早的時間抵達。此處採預先知道請求與確定性排程的集中規劃假設，並非在第一包實際抵達第10秒之後才收到g=1的第二包。

## 候選Label與Q

第二包來源延伸產生L1(c3,{2})、L2(c3,[9,11])、L3(c4,[13,28])、L4(c6,[3,19])；先處理下界2的L1，但它無法等到B的任何下一跳。接著L4產生L5(c7,[17,30])、L6(c8,[5,9])及L7(c8,[11,14])。

Q依下界為L6:5、L2:9、L7:11、L3:13、L5:17。選L6抵達5秒，回溯到c8起送4、C抵達3、c6起送1。取得具體可行時間5後，其餘下界皆不早於9，本例可依候選下界規則停止。L2/c4分支的後續頁面標明是補充解析，不冒充停止後仍執行的Q步驟。

K仍須配合 `a∈K 且 a≤s`，不能把前驅抵達與起送區間任意組合。一般正確性、區間完整性、時間相關性與端點處理尚待實作及證明。
