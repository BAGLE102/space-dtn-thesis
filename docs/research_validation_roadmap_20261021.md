# 研究規劃：從 contact splitting 重疊查核到可驗證的貢獻

日期：2026-10-21。這是工作計畫，不是新演算法定稿或實驗結果。

## 1. 目標與目前狀態

目標：在不可切分 bundle、有限 contact 時窗與節點 buffer 下，計算對既有預約可行的最早抵達排程，並找出相對既有工作的可驗證差異。

暫定問題敘述：

> 已知 Contact Plan 與先前接受 bundles 的資源預約，在 bundle 完整接收後才能轉送的條件下，求滿足傳送、接收與等待期間 buffer 限制的最早抵達路徑及各跳起送時間。

- 已確認：2410.15546v3 已提出 contact splitting、forecast buffer tables、等待跨溢位的銜接剪枝與逐包更新；不能單獨當作新貢獻。
- 候選差異：逐 byte 接收／釋放下的可行起送時段計算，以及對受限等待的搜尋狀態設計。
- 未確認：差異是否已被其他工作處理、候選是否完整正確、是否更有效率。
- 現有 PPT 有固定排程的手算／數值核對；沒有完成通用起送區間求解器或新方法效能驗證。
- 網站、舊程式與 PPT 不是同一版，不能用舊程式結果替候選方法背書。

版本：本計畫討論使用者同意的 `1021_起送時段修訂版.pptx` 候選。AGENTS 指定的 v04／snapshot 文件保留為既有程式基準，差異需在實作前對照，不直接覆寫。

## 2. 主線與優先順序

只保留一條主要驗證主線：**精確處理接收與釋放同時發生時的可行起送時段，再驗證搜尋能否找到最早可行結果。**

獨立 quota、允許循環、來源／目的地也受 buffer 限制都先列成明確的模型選項。每個選項要有需求或案例；不能為製造差異增加限制，也不能未經確認從候選刪除。

優先順序：模型對齊 → 最小案例 → 獨立正確性對照 → 區間與搜尋實作 → 效能實驗 → PPT／論文貢獻定稿。

## 3. 階段一：固定一頁模型對照表

先列「論文原模型」「目前 PPT 候選」「同模型比較設定」，並記錄每個假設的來源與影響。

| 項目 | 要確定的內容 | 判斷影響 |
|---|---|---|
| 規劃方式 | 固定順序逐包接受，前包不重排 | 單包最早不代表整批最佳；順序影響接受率 |
| Contact | 單向、時窗、固定速率、傳播延遲、時窗代表發送可用時間 | 決定最晚起送與完整抵達公式 |
| Bundle | 不可切分、無複製、完整接收才能轉送 | 決定 buffer 曲線與下一跳最早時間 |
| Contact 資源 | 傳送預約禁止重疊；容量由時間導出或另有獨立 quota | 若有 quota，須說明管理／物理來源與計量方式 |
| Buffer | 接收逐 byte 增加、送出逐 byte 釋放或整包預留 | 可能改變可行集合，不能全算作搜尋演算法優勢 |
| 等待 | 完整抵達到下一跳起送的整段都要放得下 | 接收可行不保證之後能等待 |
| 同時事件 | 沿用候選 P，明定交付釋放與新來源接納順序 | 邊界等號與來源／目的地須特別處理 |
| 路徑 | 無循環或允許重訪節點／contact | 雙方必須同條件；單向圖本身不保證無循環 |
| 設備 | 是否可同時收送、共享天線／收發機限制 | 同時收送案例必須有硬體依據；目前候選未納入設備互斥 |
| 資訊 | 已知預約完全準確、集中規劃 | 結論限理想資訊；不能推廣到未知流量／延誤 |
| 範圍 | 有限規劃上限、deadline、時間精度 | 區分期限內無解、未知與搜尋超時 |

容量選項處理：先保存 A3b 候選。若實際容量完全由可用傳送時間推得，提出改採派生容量的候選修正；經使用者確認後才改定義與程式。

通過條件：同一輸入給不同實作者，不會因 buffer 釋放或時窗語意不同而得到不同的可行性判斷。

產出：模型對照表、待決事項、PPT／舊程式版本差異表。

## 4. 階段二：先做最小區分案例

核心案例：B 容量 4 MB；新包 4 MB；接收速率 4 MB/s；延遲 0。A→B 時窗 [1,10]，B→D 時窗 [8,9]。前包在 B 的占用於 7 秒前為 4 MB，7～8 秒以 4 MB/s 下降，8 秒後為 0。前包使用另一條 outgoing contact，假設設備允許同時收送。

候選排程：新包 7～8 秒接收、8～9 秒送出，9 秒到 D。接收期間背景與新包占用合計為 4 MB。

這是可分析案例，尚不是已重現論文的反例。若採整包接收預留，模型結果本來就可能不同。

每個方法輸出：可行起送集合、選定時間、每跳排程、buffer 峰值、拒絕原因。重現 Algorithm 2 時逐步對照原文，對模糊的時間映射明確記錄，不能故意用較弱版本作對照。

| 診斷案例 | 必須檢查的問題 |
|---|---|
| 整段無背景占用 | 能否取得基本最早排程 |
| 前半段滿、後半段可用 | 是否把整條 contact 錯刪 |
| 同時釋放與接收 | 接收 ramp 是否精確、設備假設是否成立 |
| 不同接收／釋放速率 | 峰值是否出現在區段交界 |
| 接收可行、等待失敗 | 是否拒絕等待跨過滿載區段 |
| 早到不能等、晚到可行 | 是否保留必要的不同持有時段狀態 |
| Contact 已占用中段 | 前後剩餘片段是否都保留、禁止重疊 |
| Contact 結尾恰好傳完 | 是否允許等號、正確計入傳播延遲 |
| 來源／目的地同時跳變 | P 語意是否一致 |
| 重訪節點／同 contact | 若允許，是否重複計量；若禁止，是否明示 |
| 無解、超時、開端點 | 能否正確區分 NO_PATH、UNKNOWN、未證最優 |

通過條件：每個案例有輸入、預期理由與實際輸出；差異能歸因到模型或實作，而非只看圖猜測。

## 5. 階段三：建立獨立的正確性對照

建議以小型精確排程 oracle 作為主檢查工具：有限 contact 序列搭配連續時間限制求解；不得重用候選的 dominance／區間剪枝來宣稱獨立。

- 先限制無循環的小拓譜，可完整列出 contact 序列，再解起送與分段線性 buffer 限制。
- 若要支援 walk，須先證明有限搜尋界或明示最大跳數。固定跳數 oracle 只保證該界內，不能直接證明一般 walk 完備。
- 求解器可考慮線性／混合整數建模；必須先確認模型能表達分段、事件側與容差，不能把一般浮點 solver 稱為精確證明。
- 逐時間格點窮舉僅作輔助回歸；可能漏掉格點間起送，不能當連續時間最優性的唯一依據，也不回到逐秒枚舉正式方法。
- 最終路徑交給獨立 schedule validator，逐段檢查接收、持有、送出、背景跳變左右值、傳送預約及容量；不可只抽樣整秒。

比較：可行／無解狀態、最早抵達值、每項資源限制；同抵達時間有多條路時不要求路徑完全一致。

通過條件：預定的小案例與固定種子隨機小案例無未解釋差異。這是實作證據，不取代一般證明。若同模型出現錯誤，保存最小失敗案例、暫停效能比較，提出候選修正交使用者確認。

## 6. 階段四：實作拆分架構

以下為責任規劃，實作時先對照既有目錄與介面；目前未建立這些模組。

| 元件 | 責任 |
|---|---|
| 輸入模型／讀取器 | node、contact、bundle、預約、模型選項；更換拓譜不改搜尋 |
| 資源時間曲線 | 分段線性 O、傳送預約與事件側；統一單位 |
| 可行起送求解器 | contact 時窗、預約、送收 buffer 求交得到 J |
| Label 搜尋 | 裁切前驅可等待範圍、每段選可取得最早時間、Q、pred、支配 |
| 獨立驗證器 | 從完整排程重算資源可行性，不呼叫搜尋剪枝 |
| 資源提交 | 驗證後原子更新；按節點造訪寫曲線，接點不重複加總 |
| 實驗執行器 | 共用輸入、seed、順序、輸出格式，執行多種演算法 |
| 視覺化 | 讀取 trace，顯示目前 label、J、Q、曲線與拒絕原因 |

候選流程：讀入 → 固定先前預約 → 取 Q 最早 Label → 掃描 outgoing contacts → 求可行起送區間 → 加上前驅等待限制 → 每段產生具體時間 Label → 合法支配比較 → 目的地回溯 → 獨立驗證 → 提交 → 下一 bundle。

重點待證：每個連通區間只取最早點是否足夠；同持有區間能否模擬較晚候選；支配是否保留必要容量／歷史；搜尋是否終止；開端點丟棄是否影響最優性。Label 欄位仍先採 `(c,A,s,pred)`，需要額外狀態時先提出理由。

## 7. 階段五：公平的對照與效能實驗

對照配置：

1. 忠實重現該文 Algorithm 1／2；找到原碼時核對版本，找不到則明寫自行重現。
2. 本研究候選；使用相同輸入與共同模型。
3. 小型 oracle；只作正確性參考，不拿小範圍速度當大規模效能基準。
4. 選做：明確定義的整包預留版本作模型敏感度分析，不能冒稱該文完整方法。

分開回答：

- 同模型算法比較：可行集合、資訊與路徑限制相同，才能判斷搜尋品質與成本。
- 不同 buffer 模型比較：解釋較保守預留與逐 byte 計量的影響，改善不能全部算成演算法優勢。

實驗變因先逐項掃描：負載、bundle 大小、buffer 上限、contact 時窗／密度、速率與延遲、背景占用、連通片數。模型固定後再做少數交互作用，避免全排列失控。

資料規模順序：PPT 兩包 → 五包可追蹤案例 → 約 100 包冒煙測試 → 約 1,000 包 → 在 runtime／記憶體預算內再試 10,000 包。這些是建議規模，不是已完成結果；每一級記錄規劃時域與負載，不能只報包數。

拓譜分層：人工診斷拓譜確認原因；參考論文／學長拓譜評估代表性；較大 Contact Plan 評估擴展性。須取得可重現節點、軌道／連線、接觸生成規則及時域，僅畫相似網路不能稱忠實沿用。

指標：

- 正確性：不可行路徑誤接受、可行路徑漏失、與 oracle 的抵達差距；均列分母與未知比例。
- 任務表現：接受／交付率、deadline 達成率、delivery delay；此處先區分規劃成功與實際模擬交付。
- 成本：每包規劃時間、P95／最大值、Label 產生與擴展數、支配刪除數、J／contact 片段數、峰值記憶體。
- 資源：各節點 buffer 峰值、實際傳輸量與可用傳輸量的使用率；獨立 quota 與實體時槽分別計量。
- 統計：平均／最小／最大／標準差、配對差與信賴區間；重複數由先導變異與精度需求決定。
- 最優差距只對有 oracle 證書的結果計算；理想值為零時不算百分比，未知與 timeout 不當成無解。
- 固定順序先公平比較；再換來源／大小／優先權與不同順序，檢查逐包貪婪對不同流量群的影響。

## 8. 正確性、外部效度與公平性風險

| 風險 | 必須採取的處理 |
|---|---|
| J 或 dominance 錯刪 | oracle 差分、保留失敗輸入；停止後續效能結論 |
| 同時收送設備不支援 | 將允許收送列為適用條件；再測設備互斥模型，不能直接外推 |
| 實際 buffer 按整包預留 | 說明逐 byte 是實作能力需求，模型結果不代表所有 BP 實作 |
| 預約資訊／contact 有誤差 | 第一階段僅主張理想排程；另測延誤或安全裕度再談實務 |
| 額外 quota 無需求 | 驗證來源；避免以人工限制製造優勢 |
| 循環／來源與目的地限制不同 | 配置相同模型比較，另報擴充模型結果 |
| 只挑有利負載／拓譜 | 同時包含無差異、優勢、失敗、高碎片與壅塞案例 |
| 順序使某群 bundles 長期失敗 | 固定順序配對、分群報接受率與延遲，再做順序敏感度 |
| 逐包最早被寫成整批最優 | 明確限制 claim；若要整批最優，另立問題與聯合排程對照 |

## 9. 決策點與研究主張

- 若同時收送案例揭露的只是模型差異：主張須聚焦該模型的必要性與精確求解，另查是否已有相同方法。
- 若共同模型下候選保留既有重現漏掉的解：先排除重現錯誤、核對論文條件，再提出可重現案例與證明；不能先寫作者錯誤。
- 若同模型結果相同但計算成本較低：可朝效率／表示方式貢獻，需理論或跨案例實測支持。
- 若無正確性、模型價值或效率差異：停止強調 contact splitting；與老師討論其他具體需求，先不同時擴充多個方向。

暫定題目：**具時間變動 Buffer 限制之 Space DTN 可行起送時段計算與路徑搜尋**。
此為工作題目；「首次」「完整」「最優」「提升」等字詞等待文獻、證明與實驗支持後再使用。

## 10. 建議工作排程與交付

下列是工作順序與約三至四週的初步安排，不是保證工期；若模型或重現遇到歧義，先解決再往下推。

| 階段 | 建議時間 | 交付與進入下一階段的條件 |
|---|---|---|
| 模型與最小案例 | 第 1 週前半 | 模型表、需求、手算曲線；相同輸入語意一致 |
| 論文重現與獨立檢查 | 第 1 週後半～第 2 週 | 案例對照、歧義清單、oracle／validator；能解釋差異 |
| 候選模組與小案例回歸 | 第 2～3 週 | J、搜尋、提交及 trace；沒有未解釋同模型錯誤 |
| 規模與敏感度實驗 | 第 3～4 週，依成本調整 | 可重現資料／圖表、限制與貢獻判斷 |
| PPT／論文整理 | 各階段通過後更新 | 問題、相關工作差異、方法、證據與未解事項 |

下一個具體工作單位只做：**模型表＋同時釋放／接收小案例＋Algorithm 2 每步對照**。先回答差異是否存在及源頭，再決定是否實作整套搜尋。

預期成果類型：模型說明、診斷案例輸入、排程與曲線、獨立核對、演算法 trace、實驗摘要。確定實作後才建立對應程式／輸出，不在此假稱已生成。
