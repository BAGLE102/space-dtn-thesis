# 外部 AI 修訂版審查：具體時間 Label 與可行起送切片

日期：2026-10-21。接續 `ai_safe_interval_review_20261021.md`。
範圍：本次使用者貼上的第二份外部 AI 回覆；不是更改正式演算法或PPT的紀錄。

## 結論與採用狀態

第二版確實修正獨立quota的容量反例。保留具體時間Label、逐個可行起送切片選最早點、以可持有時段區分候選的方向值得保留為候選方法。
新容量dominance是可論證的保守充分條件，尚不是已完成實作及形式化證明的研究成果。
Rule B為新增的保守模型；不能把它當成與所有事件順序等價的純記號調整。
本次不修改演算法、不更新簡報、不進行效能比較；先保存需要修訂的內容。

## 已補上的內容

| 項目 | 審查 |
|---|---|
| 具體Label `(c,A,s,pred)` | 保留，時間在建立時確定；沒有必要直接改成抵達區間Label |
| 派生容量／獨立quota分開 | 必要且合理；兩者不能混在同一個正確性主張中 |
| 獨立quota檢查 `S*(n(L,c)+1)<=R[c]` | 修正之前逐次只檢查S的問題；次數可沿pred鏈回算，不代表比較時可忽略 |
| 支配比較加入使用次數 | 同節點、同可持有時段，A較小且相關contact次數逐項不多，是保守的充分條件 |
| 每切片選 `max(A,lo)` | 固定同一前綴與contact時，使用次數相同；容量並不額外區分同切片內不同起送點 |
| source／destination與三種期限 | 有提出明確候選規則；但仍是新增模型約定，非自動生效的既定研究定義 |
| 循環例子 | 與前次保存的精確有理數固定排程檢查相容 |

使用次數支配不必要求向量完全相等；較早且逐項不多已足夠。
反過來，不能把這個充分條件寫成完整必要條件的「當且僅當」：較多的使用次數未必真的會妨礙任何可行後續路徑。

## 仍須修正的內容

### 1. 跳變模型的結果狀態與虛擬碼不一致

外部回答承認遇到不可取得最早點時丟棄切片，可能漏解；但整體虛擬碼仍無條件地：
- 第一個目的地Label取出就直接return。
- Q空就回傳 `NO_PATH_WITHIN(D*)`。

在尚未證明這類切片不會造成漏解前，不能把這兩個返回值解讀為原問題的最早抵達或無解證明。
目前至少需要區分：已驗證完整性前提下的最早解／無解、有排程但未證最早、因跳過未處理切片而未知、運算逾時。
即使跳過的切片只有下確界，它的後續也可能在較晚、固定的出發時刻匯合；不能只由「這一跳最小值取不到」直接推論整條路徑沒有最早解。
另一方面，本次沒有構造出其全部Rule B與合法前驅限制下必然產生這個情況的完整新反例，因此此項是未證的返回值條件缺口，不是宣稱已反駁其連續曲線下的命題。

### 2. Rule B會改變可行集合

Rule B使用背景占用的事件前後最大值，再加上目前bundle在該時刻的占用。這通常較嚴格，未必等於「總占用在事件前後的最大值」。

明確的來源事件例子（精確有理數核對）：
- 上限1；既有bundle於t=1交付，事件前占用1、事件後0。
- 本包在g=1出現，事件前0、事件後占用1。
- 採「先釋放、再接納」：總量事件前1、事件後1，峰值1，可行。
- Rule B來源檢查：`max(1,0)+1=2>1`，拒絕。

這不是Rule B自身正確性的反例，而是證明它與另一個合理事件順序不等價。若採用，PPT必須明寫保守事件規則及其排除的排程。
不能一方面說採Rule B，另一方面把先釋放再接納的排程當成必須找出的解。

### 3. 區間求解虛擬碼仍不是完整可實作版本

- `receiverViolations`只有文字註解，沒有完整程式步驟。
- `earliestStart`仍有 `or ...`，不算完整定義。
- `senderViolations`解嚴格不等式後，仍須與有效s範圍相交並保留開閉旗標；不能把結果統一視為開區間。
- 開線段與獨立轉折點的聯集、零長度交集、只有一個可行時間的集合都要有明確規則。

其分段線性端點計算法有數學依據，但上述缺口必須補上再實作；目前未完成新求解器。

### 4. 提交buffer的描述仍有重複計算風險

外部回覆同時寫「對O_u加入持有與釋放」「對O_v加入接收與持有」，但中繼節點是前一跳接收端、下一跳傳送端，沒有指定持有段由哪一邊唯一寫入。
應對每次節點停留建立一條完整曲線且只加一次：接收上升、整包等待、傳送下降；來源與目的地分開處理。
本次尚無commit實作，所以這是定義歧義與實作風險，不能宣稱已發生雙算。

### 5. 精確性／效率／貢獻文字要降回候選

- 「派生容量精確」仍需前提：有限精確輸入、切片與端點處理完整、存在所需最小值、dominance與同包不重疊論證成立。
- 獨立quota下需維持 `(A,使用次數)` 的Pareto候選，不能期待每個節點每時段只留一個Label。
- 不逐秒枚舉不等於已證明實際較快；狀態與切片數、預處理及Pareto比較都會影響成本。
- PPT草稿的「貢獻在於推廣」應改成「候選方法／可能研究方向，尚待相關工作與正確性驗證」。
- SIPP是方法依據，不是DTN逐byte資源模型的直接正確性證明。
- Zeitz的2022論文可以確認存在；其non-FIFO一般模型複雜度不能直接套用本題。PPT不需為此新增NP-hard主張。

## PPT可用與不可直接使用的部分

可整理成候選方法頁：問題與假設、四欄Label、可持有時段、起送切片、前驅等待裁切、兩種容量定義、加上次數的支配充分條件、已核對的固定排程反例。

必須改寫後才使用：Rule B與來源接納示例、結果狀態與停止宣稱、commit曲線、完整切片虛擬碼，以及「精確」「效率提升」「貢獻」等結論。

尚需使用者決定：R是否獨立quota、事件採Rule B或明確先後順序。不能因外部AI建議就默默替換既有模型。
