# 現行 Problem Formulation（2026-11-23）

本文件依目前程式（`src/experiments/dtn_validation/dtn/`）整理，定義現行版本的問題。演算法見 `docs/pseudocode_20261123.md`。

舊文件 `sequential_label_setting_v04.md`、`current_algorithm_snapshot_v01.md`、`formal_problem_algorithm_definition_v01.md` 保留不改，差異列在第 8 節。

## 1. 一句話定義

在已知的衛星 contact plan 上，bundle 依產生時間一包一包到來。對每一包，在不與已排定的傳輸衝突、且所有節點 Buffer 每一刻都不超過上限的條件下，找出一條路徑與每一跳的出發時間，使它最早送達目的地；找不到就拒絕。

## 2. 系統假設

1. **排程式 DTN**：所有 contact 的開始、結束時間、速率、傳播延遲事先已知。
2. **集中規劃**：規劃者知道全網目前已排定的傳輸與各節點的 Buffer 占用。
3. **Bundle 不可分割**：整包走同一條路徑，不拆開走多條路。
4. **連線獨占**：同一條 contact 同一時間只傳一個 bundle，用全部速率；速率與延遲在 contact 期間固定。
5. **連續時間**：時間是連續的，以精確有理數計算，不用時間槽或格點。
6. **Buffer 逐步占用**：收多少占多少，送多少空多少，占用量隨時間線性變化。
7. **來源**：bundle 在產生時刻 g 整包出現在來源，算入來源 Buffer。
8. **目的地**：收的期間算入目的地 Buffer，整包收完的瞬間交付並離開。
9. **路徑不重複經過同一節點**（2026-11-23 決定）。
10. **轉送方式**二選一：收完才轉（store-and-forward，預設），或邊收邊轉（cut-through）。
11. **依序規劃**：前面已接受的包不再改動；後面的包在它們留下的狀態上規劃。

## 3. 輸入

**Contact plan**：每條 contact c = (u, v, a, b, r, d)

| 符號 | 意思 |
|---|---|
| u, v | 從節點 u 傳到節點 v（有方向） |
| [a, b] | 開放時間 |
| r > 0 | 速率（MB/s） |
| d ≥ 0 | 傳播延遲（秒） |

**網路狀態**（由前面已接受的包決定，規劃這一包時固定不變）

| 符號 | 意思 |
|---|---|
| F_c | contact c 已預約的傳輸時段集合，每筆是 (x, y) |
| O_n(t) | 節點 n 在時刻 t 的已占用量（分段線性，可有瞬間跳變） |
| M | 每個節點的 Buffer 上限（目前所有節點相同） |

**目前這一包** b = (src, dst, g, S)，以及期限 T。

| 符號 | 意思 |
|---|---|
| src, dst | 來源、目的地 |
| g | 產生時間 |
| S | 大小（MB） |
| T | 期限，必須在 T 之前送達 |

記號：τ_i = S / r_i 為第 i 跳的傳輸時間；ramp(t, x, y) 為從 x 到 y 由 0 線性升到 S 的函數。

## 4. 決策變數

一條路徑 p = (c_1, c_2, …, c_k)，以及每一跳的出發時間 s_1, s_2, …, s_k。

由此導出第 i 跳（i ≥ 2）在中繼節點 n_i = c_{i−1}.v 上的時刻：

| 符號 | 定義 | 意思 |
|---|---|---|
| h_i | s_{i−1} + d_{i−1} | 開始收 |
| A_i | h_i + τ_{i−1} | 收完 |
| f_i | s_i + τ_i | 送完 |

到達時間：Arr = s_k + τ_k + d_k。

## 5. 限制式

**(1) 路徑銜接**：c_1.u = src，c_k.v = dst，c_i.v = c_{i+1}.u。

**(2) 不重複經過節點**：src、c_1.v、c_2.v、…、c_k.v 兩兩不同。

**(3) 產生時間**：s_1 ≥ g。

**(4) Contact 開放時間**：c_i.a ≤ s_i，且 s_i + τ_i ≤ c_i.b（要在 contact 結束前傳完）。

**(5) 期限**：Arr ≤ T。

**(6) 連線獨占**：對每筆 (x, y) ∈ F_{c_i}，s_i ≥ y 或 s_i + τ_i ≤ x（不和已預約時段重疊）。

**(7) 轉送條件**（每個中繼，i ≥ 2）：

- 收完才轉：s_i ≥ A_i
- 邊收邊轉：s_i ≥ h_i 且 f_i ≥ A_i，即 s_i ≥ max(h_i, A_i − τ_i)（已開始收，且送完不早於收完）

**(8) Buffer**：這一包在各節點的占用量 own_n(t)：

| 節點 | own_n(t) | 停留期間 |
|---|---|---|
| 來源 | S − ramp(t, s_1, s_1 + τ_1) | [g, s_1 + τ_1] |
| 中繼 n_i | ramp(t, h_i, A_i) − ramp(t, s_i, f_i) | [h_i, f_i] |
| 目的地 | ramp(t, h, A)，A 之後為 0 | [h, A]，h = s_k + d_k，A = h + τ_k |

要求：在停留期間的每一刻 t，O_n(t) + own_n(t) ≤ M。

## 6. 目標

最小化這一包的到達時間 Arr。可行解不存在時拒絕這一包（未送達）。

## 7. 接受後的狀態更新

1. 每一跳：F_{c_i} ← F_{c_i} ∪ {(s_i, s_i + τ_i)}。
2. 每個經過的節點：O_n ← O_n + own_n。

所有包處理完後的評估指標：送達率、平均延遲（Arr − g）、每包計算時間。

## 8. 與舊定義文件的差異

| 項目 | 舊定義（v04，10 月） | 現行 |
|---|---|---|
| 時間 | 時間格點 Δ | 連續時間（精確有理數） |
| 連線資源 | 累積配額 U[c] + S ≤ R_c，不檢查忙碌時段 | 連線獨占：不得與已預約時段 F_c 重疊 |
| 路徑 | 允許重複經過節點與 contact | 不重複經過節點 |
| 轉送 | 收完才轉 | 收完才轉或邊收邊轉 |
| Label | 單一到達時間 (v, a, U) | 可出發區間 (c, [lo, hi], pred) |

Buffer 模型（來源從 g 起占、逐步占用、目的地收完交付）與目標（最早到達）沒有改變。

## 9. 尚未定案（需和老師確認）

1. **目的地 Buffer**：目前目的地受上限限制，且指定單一目的地。黃文龍學長的模型中，hot spot 不受 Buffer 上限，送到任一 hot spot 即算送達。
2. **論文主模型**用收完才轉或邊收邊轉。
3. **rate 是否明存**：目前斜率由 O_n 相鄰兩點算出，只知道淨值。
4. **驗證規則的寬鬆處理**：本文件第 5 節 (8) 寫的是「每一刻都不超過」；程式在本包占用為 0 的時刻不檢查，只在背景本身已超過 M 時會有差別。是否收緊尚未決定。
