# 本研究的用詞對照與寫作原則

本表是本專案採用的中文說法，不宣稱所有詞都有臺灣學界一致的標準譯名。英文保留供查閱原文；說明以臺灣繁體中文為主。這次只釐清用詞，沒有變更演算法、判別式、數據或保證範圍。

## 先修正容易誤解的說法

### 「資源快照」改為「本次搜尋使用的資源資料」

指開始替某個 bundle 找路時，已知的 contact 剩餘可分配資料量 R_c，以及各節點在不同時間的既有 buffer 占用 O_v(t)。這些資料在這一次搜尋中保持不變；路徑與排程確定後才更新，供下一個 bundle 使用。

O_v(t) 包含已排定的未來占用，不只是當下已用多少 buffer。「snapshot」在軟體領域有其用途，但原文件直接稱為「資源快照」，沒有把時間範圍說清楚，容易誤解。

### 不再使用「免費等待」

先前想表達：模型沒有另外設定等待費用、能量消耗限制等項目。這不表示等待沒有影響：等待會延後傳輸，bundle 留在節點期間也持續占用 buffer。

舊版無其他 buffer 占用的基準模型，可以在容量足夠的節點持續等待；目前依序處理多個 bundles 的版本，必須檢查整段等待期間是否會超過 buffer 上限。兩者不能混用。

改寫為：「模型未另外計算等待成本；等待期間仍須符合 buffer 容量限制。」若只討論能不能等，直接寫「等待期間不會超過 buffer 上限」。

### 不單獨使用「安全」

- 原「安全等待」：改為「等待可行」，即整段等待期間不會超過 buffer 上限。
- 原「安全刪除 label」：改為「刪除後不影響最佳解」，須有支配條件與證明支持。
- 原「安全路徑」：若只檢查了部分路徑，就寫「目前已走的部分符合限制」，不能暗示保證抵達目的地。

### 「凍結演算法」改為「固定演算法版本」

只是為了讓驗證時有同一份定義可比較，不是演算法本身的動作。

## 用詞對照

| 原文件用詞 | 後續中文說法 | 在本研究中的意思 |
|---|---|---|
| Label Setting Algorithm | Label Setting 演算法 | 保留老師指定的方法名稱；不強行使用不熟悉的中文譯名 |
| label | 標籤（label） | 記錄某條候選路徑目前節點、完整到達時間及已用資源的資料 |
| state | 狀態 | 判斷後續傳輸所需的資訊；具體欄位依標籤定義說明 |
| label extension / extension | 標籤延伸 | 嘗試透過下一個 contact 傳送，建立新的標籤 |
| feasibility / feasible | 可行性／可行 | 是否符合模型中的全部相關限制 |
| dominance / dominance rule | 支配關係／支配規則 | 一個標籤能取代另一個標籤的後續選擇，且結果不較差 |
| pruning | 刪除不必繼續搜尋的標籤 | 本研究多指依支配規則刪除標籤；不是把整個節點刪掉 |
| conservative dominance | 較保守的支配規則 | 確認能取代才刪除，可能留下較多標籤；不是另一種資源限制 |
| candidate | 候選項目 | 正在考慮但尚未選定的路徑、標籤或發送時間，要寫清楚是哪一種 |
| prefix | 已走過的部分路徑 | 從來源到目前節點的傳輸安排 |
| suffix / continuation | 後續路徑與排程 | 從目前節點繼續到目的地的傳輸安排；此處包含發送時間 |
| continuation preservation | 刪除標籤後仍能保留最佳解 | 被刪標籤的可行後續，能由保留標籤以同樣好或更好的結果取代 |
| invariant | 每個搜尋步驟都成立的性質 | 例如每個保留的標籤都對應到符合限制的部分路徑 |
| queue / priority queue | 佇列／優先佇列 | 存放待處理標籤；目前依完整到達時間排序 |
| query | 一次路徑搜尋 | 替目前這個 bundle 找路，不代表網路中只有這一包 |
| contact | 通訊機會（contact） | 指定節點間，在某段時間內可傳輸的機會，包含速率與傳播延遲 |
| contact window | 可傳輸時段 | 本模型指發送端可使用的時間區間 |
| bundle | bundle（本研究要傳送的完整資料單位） | 不把 bundle 與底層網路封包任意互換；日常解說可用「這一包」 |
| quota / residual quota | 可分配資料量／剩餘可分配資料量 | 一個 contact 還允許分配多少資料量；單位如 MB，不是 MB/s |
| aggregate quota model | 只限制總可分配資料量的模型 | 檢查資料量，但不表示已知道每個傳輸空檔的位置 |
| buffer / occupancy | 緩衝區（buffer）／占用量 | 節點用來暫存資料的空間／在某時刻已使用的空間 |
| reservation | 資源預約 | 記錄已選定路徑在未來哪些時段會使用哪些資源 |
| background occupancy | 先前已排定的 buffer 占用 | 目前主要由先前已接受的 bundles 形成，不暗示額外外生流量 |
| commit | 確認排程並更新資源預約 | 找路成功且檢查完成後，才扣除資料量並記錄占用時段 |
| transmission calendar | 已排定的傳輸時段表 | 記錄各 contact 哪些時段已被使用，用來找連續可用時段 |
| store-and-forward | 儲存後轉送 | 本研究要求整個 bundle 接收完成後，才能開始下一跳 |
| non-fragmented | 不可分割 | 不將 bundle 拆成多個部分分開傳送 |
| non-preemptive | 傳輸不可中斷 | 一跳開始後連續傳完整包，不能先停下再接續 |
| earliest arrival | 最早完整到達時間 | 以整包抵達目的地的時間作為比較目標 |
| walkthrough | 演算法逐步執行範例 | 逐步列出佇列、延伸、判別式與刪除結果 |
| enumerate / exhaustive enumeration | 逐一列舉／完整列舉 | 對指定範圍內的選項逐一檢查；必須交代列舉的是路徑或時間 |
| independent exhaustive oracle | 獨立列舉驗證程式 | 不使用待驗證演算法的搜尋與刪除規則，另行列出小型問題的完整候選以核對答案 |
| oracle result | 列舉驗證程式得到的參考答案 | 本次僅對同一個離散時間模型成立，不是所有情境的絕對答案 |
| proposed algorithm | 本研究目前的演算法 | 不交替使用 proposed、提案算法等說法 |
| baseline | 比較基準 | 要寫明是基準模型、基準演算法還是基準結果 |
| finite grid / time grid | 有限的離散時間點／時間間隔 | 例如只嘗試 0、1、2…秒開始傳送 |
| horizon | 規劃時間範圍／規劃截止時間 | 只考慮指定時間內的傳輸與到達 |
| continuous time | 連續時間 | 開始傳送的時間不限制為固定間隔，可為 1.5 秒等時間 |
| event point | 狀態改變的時間點 | 如 contact 開始、既有占用改變、或占用量碰到容量上限的時刻 |
| completeness | 搜尋完整性 | 是否保留找到最佳解所需的候選，不是要求所有被支配路徑都保留 |
| counterexample / witness | 反例／具體佐證案例 | 反例用來推翻一個明確主張；佐證案例不一定表示演算法有錯 |
| gate | 是否繼續執行的檢查 | 驗證程式的控制流程，例如發現不一致就停止；不屬於路由演算法 |
| exact arithmetic | 精確數值運算 | 本次使用分數運算，避免小數誤差影響判斷 |
| FIFO | 較早出發不會比較晚出發更晚到達的性質 | 描述時間相依邊的性質；不可因此忽略等待期間的 buffer 限制 |

「可行」與「最佳」分開使用：符合限制只是可行；在所有可行選擇中到達時間最早，才是本題的最佳解。「沒有找到反例」也不等於「已證明所有情況正確」。

## 後續文件原則

1. 用中文敘述概念，必要英文在第一次出現時括註；保留 Label Setting、SPPRC、CGR、DTN 等方法或協定名稱。
2. 同一概念使用同一說法，不交替使用「資源快照／固定背景／snapshot」卻不解釋。
3. 公式、程式變數、檔名和論文標題不因翻譯任意改名，避免破壞重現方式。
4. 說明「有限的離散時間點」之後才簡稱「離散時間版本」，不混稱連續時間版本。
5. 優先說實際動作，例如「扣除已選路徑使用的資料量」，不只寫「提交資源」。
6. 舊版說法及原始驗證記錄可用本表對照；尚未逐份改寫的舊文件不表示那些用詞仍是後續採用的寫法。
