# Space DTN 研究背景、動機、目的與目前進度

整理日期：2026-10-25。最近一次實驗日期：2026-10-21。

本稿依英文簡化技術寫作草稿逐段翻譯。ASD-STE100 規範英文寫作；本中文稿不宣稱為 ASD-STE100 合規文件。

## 1. 研究背景

太空網路不一定能持續提供來源節點到目的節點的完整路徑。延遲容忍網路（Delay-Tolerant Networking，DTN）支援這類情況下的資料傳送。節點先保留資料，等到 contact 可用時再傳送。

本研究以 bundle 作為路由方法需要傳送的資料單位。每個 contact 包含傳送端、接收端、可用時窗、資料速率與傳播延遲。Contact Plan 記錄這些 contacts。

本研究將每個 bundle 視為不可切分的完整單位。同一跳的傳輸不能將一包拆到不同 contacts。節點必須完整收到 bundle，才能將該包傳送到下一個節點。

每個節點都有 buffer 上限。先前 bundles 可能使用後續 bundle 也需要的 contact 時間與 buffer 空間。因此，路由方法必須依據目前的資源預約規劃路徑。

## 2. 研究動機

Contact 的總容量足夠，不代表存在足夠長的連續傳送時槽。一條 contact 可能在已占用時段之後，仍有可用時槽。路由方法必須找出足以完整傳送 bundle 的時槽。

整包抵達時的 buffer 空間足夠，不代表接收過程一定可行。接收期間的占用量必須持續符合 buffer 上限。節點保留或傳送 bundle 時，也必須符合相同上限。

較早抵達的 bundle 可能需要等待，而等待期間可能沒有足夠的 buffer 空間。較晚抵達可以避開該時段。因此，不能只依抵達時間，判斷一個 Label 能否取代另一個 Label。

早期草稿在時間格點上測試不同的起送時間。目前的候選方法改為計算可行起送區間。這項改動可避免為每個時間格點建立 Label。

## 3. 與既有研究的關係

文獻比對發現，目前方法與一篇既有研究高度重疊。該研究已使用 contact 切割、buffer 預測及 contact 銜接限制。它也逐包規劃路徑，並更新資源預約。

因此，這些功能不足以支持本研究提出新方法的主張。本研究必須找出具體差異，並驗證該差異。其中一個候選差異是資源計算的成本。

## 4. 研究目的

**本研究的主要目的，是在既有資源預約下，找出每個 bundle 最早可行的抵達時間。輸出必須包含完整路徑，以及每條 contact 的實際起送時間。**

第一，建立一致的時間、contact 容量與 buffer 限制定義。這些定義必須區分 contact 是否可用，以及接收端是否有足夠的 buffer 空間。

第二，計算可行起送區間，取代時間格點枚舉。每個區間都必須符合 contact 時窗與適用的資源限制。

第三，驗證搜尋是否保留所有必要的候選路徑。完整路徑必須在接收、儲存與傳送期間持續符合 buffer 上限。方法也必須區分搜尋未完成，以及已證明沒有可行路徑這兩種結果。

第四，在相同模型與輸入資料下比較方法。比較項目包括抵達時間、計算時間、記憶體用量與失敗案例。

另一個候選目的是減少重複的資源計算。候選方案僅在查詢需要時計算區間，並重用仍有效的結果。本研究尚未確認這項方案能形成新的研究貢獻。

## 5. 目前進度

目前已整理候選 Label 定義與路徑搜尋流程，並以固定路徑案例支援簡報說明。完整候選搜尋尚未完成經驗證的實作。

目前另有一個處理連續 buffer 曲線的區間元件。九個解析案例的結果符合預期區間。9,307 次固定起送時間比較，以及 22,320 次快取答案比較，均未發現差異。

上述檢查不能證明完整路徑搜尋正確。元件實驗使用 96 個 contacts 與五個資源快照。每種策略重複計時七次。

在查詢約 10% contacts 且僅局部更新資源的案例中，按需策略的時間中位數為 28.443 毫秒。增量全量策略為 228.056 毫秒。兩者均為處理五個快照的總時間。

當查詢涵蓋全部 contacts 時，按需策略沒有穩定的時間優勢。這些結果只支持有條件的元件效益。該實驗未將候選方案與已發表的演算法實作比較。

## 6. 研究範圍與待處理問題

目前路由模型依固定順序逐包規劃，並假設 contacts 與資源預約已知。這個模型不處理所有 bundles 的聯合最佳化。

目前元件實驗未納入前驅等待、占用曲線跳變與完整路徑的資源更新，也未納入隨機 contact 失效與共用收發設備限制。因此，現有結果不能證明實際部署效能或完整搜尋的最優性。

本研究的貢獻仍待確認。下一個驗證步驟，是量測完整搜尋實際產生的資源查詢。這項量測必須確認按需計算能否降低整體路徑規劃時間。

| Space DTN | 採用 DTN 的太空網路 |

| feasible start interval | 滿足指定資源條件的起送時間區間 |

| predecessor | 候選路徑中的前一個 Label |
