# 學長論文重讀摘要（2026-11-11）

兩本都是李詩偉老師指導的中正大學通訊工程研究所碩士論文（114 學年度）。
本文是逐頁重讀後的整理，原始 PDF 不納入 Git。

## 一、黃文龍：延遲容忍衛星網路之路由規劃與封包發送排程（46 頁）

### 問題與模型

- 多筆 flow 在 contact plan 上的路由與排程，建成**時間槽化的 multi-commodity flow 線性規劃**，用 CPLEX 22.1.1 求解。
- 決策變數：
  - 每條 flow 在每個 contact（時間槽）上的傳輸量 x
  - 每條 flow 在每個時間槽、每個節點的 buffer 占用 b
  - hot spot 已收到的量 y
- 限制式：
  - (1) contact 容量：所有 flow 的量總和不超過 c_l
  - (2) 流量守恆：**流入 − 流出 = b_t − b_{t−1}**（來源另加生成量）
  - (3) 開始前沒有占用
  - (4) 每個時間槽的 buffer 總和不超過上限（hot spot 除外）
  - (5) 截止前全部送達
  - (6) 生成槽不能從外部流入
  - (7) y 的定義
  - (8)(9) 非負
- 目標式 (A)：最小化「每單位資料送達所花時間」的總和。另有 (B)～(D) 三個變形：時間的算法不同，或改用完成比例。
- 資料可分割，同一 flow 可以走多條路徑。資料在同一個時間槽內可以流入再流出節點。

### 時間槽切割（第三章）

- 固定長度切割的問題：
  - 時間槽太多，算太久。
  - 同一槽內「先到、後送」造成計畫外的 buffer 占用（圖 5、6）。
- 改法：在拓樸變動點（contact 起訖時間）切割。
- 太短的槽直接棄用：實驗中棄用 ≤ 5 秒的槽，共 1,227 秒，約犧牲 1.4% throughput。
- 結果：2,221 個時間槽、17,180 個 contact-slot，平均每槽 38.35 秒。
- 結論章自評：切割點應該也納入 flow 的生成與截止時間。

### 實驗

- **拓樸**：Fraire、Feldmann、Burleigh，ICC 2017 的 cross-linked ring road。
  - 47 節點：6 hot spot、25 cold spot、16 衛星
  - 頻寬 100 KB/s
  - buffer 30,000 KB（他自己設定，原論文沒有）
  - 86,400 秒，3,172 條 contact
- **對照組**：CGR-deltime（最早送達）、CGR-hops（最少跳數）。先用 CGR 定好路徑，再交給 LP 只做排程。
- **指標**：目標值，以及能否全部送達（無解即視為壅塞）。
- **實驗 1～10**：
  - flow 數：50～175
  - demand：300～3,000 KB，或平均 1,500／1,800／1,875 KB 加上不同標準差
  - 生成槽：1～1000
  - 截止槽：生成槽 + 500 到 2,221 之間隨機
  - 來源分三種：cold spot、衛星、集中在少數 cold spot
  - 另有同時生成的情境
  - 實驗 10 用 50 組 pattern，畫出無解機率
- **結果**：
  - 負載低時三者差不多。
  - 負載高時 CGR 先出現無解；opt 在所有測試中都有解。
  - CGR-hops 的目標值約為 opt 的 2.5～2.8 倍（衛星發起的情境）。
- **致謝**：提到老師要求做實驗時要用統計的信賴區間。

## 二、吳峻至：基於拉格朗日鬆弛之 SVC 視訊會議路由演算法（63 頁）

- **問題**：多人視訊會議中，每位參與者是 sender 也是 receiver。每個 sender 的每個 SVC 層各建一棵多播樹。
- **限制**：鏈路容量、端到端延遲 D_max、層級相依（要先收到低層才能收高層）。
- **目標**：最大化加權滿意度。
- **方法**：
  - 先寫成 ILP。
  - 鬆弛「路徑—樹耦合」(8) 與「容量」(10)，拆成兩個子問題：
    - 子問題 A：每組 sender、receiver、layer 在延遲限制下的最小成本路徑
    - 子問題 B：每個 sender、layer 的樹選哪些鏈路
  - 用次梯度更新乘子。
  - Primal feasible heuristic 修成可行解，記錄 LB。
  - 對偶值當 UB，回報 gap。
- **實驗**：
  - 網路：Pioro40、France 兩個網路，約一半核心鏈路設成瓶頸。
  - 對照組：BSMA。
  - 指標：總滿意度與 gap。
- **結果**：
  - 60 人時，LR 的 gap 約 4.6～6.0%，BSMA 約 13～18%。
  - ILP 和 LR 的比較（Pioro40）：
    - ILP 求解時間：25 人時 16,388 秒；30 人以上算不完。
    - LR 求解時間：60 人時 345 秒。
    - 解的品質：LR 在 5～15 人時與 ILP 最佳解完全相同；20、25 人時只差 1 分、5 分。

## 三、與本研究的對照

| 項目 | 黃文龍 | 本研究 |
|---|---|---|
| 時間 | 時間槽（離散，平均 38 秒） | 連續時間，以分數精確計算 |
| 資料 | flow 可分割、可多路徑 | bundle 不可分割、單一路徑 |
| Buffer | 每個時間槽檢查一次 | 每個時刻檢查（分段線性的上確界） |
| Buffer 變化 | b_t − b_{t−1} = 流入 − 流出 | O_n 每段斜率 = 流入速率 − 流出速率 |
| 轉送 | 同一槽內可流入再流出（類似 cut-through） | 可選 store-and-forward 或 cut-through |
| 求解 | 全域 LP（CPLEX），一次規劃全部 flow | 逐包、區間 Label 搜尋 |
| 對照組 | CGR 定路徑，再交給 LP 排程 | 簡化 SR-CGR |

### 推測（未經老師確認）

- 老師說「Buffer 成長是因為輸入大於輸出、要用斜率判斷」，對應黃文龍的流量守恆式 (2)。本研究的 O_n 是它的連續時間版本。
- 老師堅持 cut-through，可能是因為黃文龍的流體模型本來就允許邊收邊送，要求兩邊模型一致。

### 可以借用的做法

1. **拓樸**：同一個 ring road（47 節點、3,172 contacts、100 KB/s）。repo 已有疑似相同的公開檔，見 `ring_road_contact_plan_source_v01.md`，但還沒逐筆確認。
2. **最佳解基準**：比照吳峻至的寫法，在小規模案例上求最佳解，回報 gap 和求解時間；黃文龍的 LP 也可以當 flow 可分割時的上界參考。
3. **實驗設計**：多組需求 pattern、回報信賴區間、畫無解機率。
4. **需求設定**：可參考黃文龍的 flow 數、demand 大小、截止時間設計。
