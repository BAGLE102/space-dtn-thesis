區間 Label Setting 逐步圖解

Space DTN：節點有資料可送就能開始轉，求每包最早抵達路徑。

舊版 v04 圖解

這個網頁在做什麼

選一個拓譜，或自己建立拓譜，然後一步一步看搜尋怎麼建立 Label、切區間、判斷 buffer，最後回溯出每一跳的起送時間。求解在你的瀏覽器中用精確分數計算。

和一般最早抵達搜尋的差別

邊收邊轉

第一個 byte 到達後，只要有資料可送，就能開始往下一跳送。

區間 Label

Label 記一段可達起送時間，到最後才決定實際時間。

Buffer Detour

節點快滿時，資料可以先離開，之後再回來。

怎麼使用

  1. 到「執行演算法」，選擇案例。
  2. 按「下一步」或「播放」。
  3. 在 buffer 圖拖動 s₂，看哪些起送時間放得下。
  4. 按左側 Label，查看它的前驅路徑。

目前的範圍

這是候選方法。小型測試未發現漏解或不可行排程，但尚未正式證明。此版本只有 RELAX 模式；未計來源與目的地背景占用，也不含獨立配額與多包提交。不要把這裡的結果當成優於既有方法的證據。

    符號
    符號意義
    

    S、g、D*Bundle 大小、可開始傳送時間、期限
    a(c)、b(c)Contact 開始、結束時間
    r(c)、δ(c)速率、傳播延遲
    d(c) = S / r(c)傳完一包所需時間
    F[c]已預約傳送時段
    O_n(t)、M_n節點既有占用、上限
    s、f = s + d起送、傳完
    h = s + δ第一個 byte 抵達
    A = s + d + δ整包收完
    L = (c, I, pred)Label：Contact、可達起送區間、前驅
    key(L) = lo(I) + d + δ最早完整抵達，Q 依此排序
    s₁*能接上 s₂ 的最晚前一跳起送時間
    

    限制
    不能送出還沒收到的資料：
  s₂ ≥ h₁
  s₂ + d₂ ≥ A₁
節點放得下：
  O_n(t) + 已收(t) − 已送(t) ≤ M_n
    

    s₂ < A₁ 是邊收邊轉，s₂ ≥ A₁ 是收完才轉，不需要另外判斷。
    

    區間的頭和尾
    Head = max( a₂, lo(I₁) + δ₁ + max(0, d₁ − d₂) )
Tail = min( b₂ − d₂, D* − d₂ − δ₂ )
對每段預約 [x, y)，移除 (x − d₂, y)
    

    只查最晚前一跳
    固定 s₂ 時，「已送」不變；s₁ 越晚，「已收」越少，占用只會變少。所以最晚的 s₁* 放不下，更早的也放不下。
    s₁* = I₁ 中不超過 s₂ − δ₁ − max(0, d₁ − d₂) 的最大值
    

    驗證與限制
    Python 原型已和 1/16 秒格點窮舉、獨立重放比對 1,864 次查詢，未發現漏解或不可行排程；這裡的瀏覽器版本另與原型比對 506 個案例，結果相同。
    這些是小型測試，不是證明。自我重疊的 TRACK 模式尚未實作；結果出現重疊時，頁面會提示答案未確認。格點之間的精度也還沒被充分檢驗。Cut-through 的協定依據與文獻查核尚未完成。
